# 装柜计算结果库存观察列设计

## 目标

在装柜计算结果中直接展示 SKU 的月销量、南非本地库存和海运在途数量，方便对照采购数量。

## 页面布局

- 在“产品名称”后依次增加“月销量”“南非本地库存”“海运在途”三列。
- 三列为只读数字，没有匹配数据时显示 `0`。
- 产品名称列缩短并允许自动换行，为新增数量列保留可视空间。

## 数据口径

- 数据统一按规范化后的“店铺 + SKU”匹配，防止不同店铺相同 SKU 串联。
- 月销量取采购建议模块最近一次保存的 `monthlySales`。
- 南非本地库存取采购建议模块最近一次保存的 `localStockQuantity`。
- 海运在途汇总采购记录中状态为 `in_transit` 的实际采购数量，并计入该记录中相同 SKU 的混装数量。
- 同一店铺和 SKU 存在多条在途采购记录时累加。

## 数据流

- `App` 将采购记录和已保存采购建议传入装柜计算页。
- 装柜计算页生成按店铺和 SKU 索引的观察数据，并附加到计算结果行。
- 结果表负责展示三列，导出工具读取相同字段生成 Excel/CSV。

## 范围

- 不修改采购数量、CBM、总金额或生成采购任务的计算逻辑。
- 不修改数据库结构。
- 不触发额外 Takealot API 同步，仅使用系统当前已保存的数据。

## 验证

- 不同店铺相同 SKU 的数据相互隔离。
- 多条海运在途记录和混装数量正确累计。
- 无匹配数据时三列显示 0。
- 页面和 Excel/CSV 的三列内容一致。
- TypeScript 与 Vite 生产构建通过。
