# 采购订单池管理员手工修改设计

## 目标

允许管理员和 owner 在采购订单池中手工修改以下字段，并在每次保存前确认：

- 整箱件数
- 每箱数量
- 尾箱数量
- 总件数
- 采购总数量
- 是否混装
- 采购单价
- 运费
- 总金额
- 单品 CBM
- 总 CBM

这些字段相互独立。管理员修改任一字段时，系统不自动联动重算其他字段。

## 权限与范围

- `admin` 和 `owner` 可以修改。
- 其他角色只读。
- 普通采购池视图和“全部装柜日期”汇总视图都支持修改。
- 汇总视图中的修改必须定位并保存到该订单所属的真实采购池。

## 编辑与确认交互

- 数值字段使用行内数字输入框；“是否混装”使用“是/否”选择框。
- 用户修改后，在输入框失焦或选择框切换时显示确认框。
- 确认文案包含产品名称或 SKU、字段名、原值和新值。
- 用户确认后才写入数据库；取消后清除草稿并恢复原值。
- 保存成功或失败继续使用页面现有消息区域反馈。
- 值没有变化时不弹窗、不保存。

## 数据模型

现有基础字段继续使用原字段保存：`cartonCount`、`unitsPerCarton`、`tailQuantity`、`isMixed`、`purchasePrice`、`freightCost`、`unitCbm`。

为会被现有计算逻辑覆盖的汇总值增加显式管理员覆盖字段：

- `manualTotalCartonCount`
- `manualPurchaseTotalQuantity`
- `manualTotalAmount`
- `manualTotalCbm`

覆盖字段为可空数值。空值表示沿用系统计算值；管理员在采购池输入数值后保存为覆盖值。数据库 `purchase_records` 增加对应可空列，采购池 JSON 同步保留这些属性。

## 读取规则

- 总件数：优先 `manualTotalCartonCount`，否则使用整箱件数加尾箱件数的现有计算结果。
- 采购总数量：优先 `manualPurchaseTotalQuantity`，否则使用现有有效采购数量算法。
- 总金额：优先 `manualTotalAmount`，否则使用现有计算结果或已保存总金额。
- 总 CBM：优先 `manualTotalCbm`，否则使用现有计算结果或已保存总 CBM。
- 汇总卡片、采购池表格、导出和后续物流/库存构建流程统一通过这些优先级读取，避免不同页面显示不一致。

## 保存规则

- 采购池内这 11 个字段的修改不调用自动重算路径。
- 保存时同时更新采购池记录快照和主采购记录。
- 汇总视图根据订单 ID 找到源采购池后更新。
- 其他页面原有自动计算行为保持不变；没有管理员覆盖值的旧记录行为不变。

## 数据库迁移

新增一份可重复执行的 SQL 迁移，为 `purchase_records` 添加四个可空数值列。同步更新主 `supabase.sql`，使全新部署包含这些列。

## 验证

- 管理员可在普通池和汇总池编辑全部 11 个字段。
- 非管理员看不到可编辑控件。
- 确认后保存，取消后恢复原值。
- 修改一个字段不会改变其他十个字段。
- 刷新页面后人工值仍存在。
- 汇总卡片、导出及下游流程读取人工覆盖值。
- 旧数据在覆盖字段为空时保持原有计算结果。
- TypeScript 构建和相关测试通过。
