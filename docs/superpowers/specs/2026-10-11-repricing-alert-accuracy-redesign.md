# 价格预警准确性重构设计

## 目标

重构价格预警的数据获取和判定链路，减少误报和漏报。系统只显示能够确认的有效预警，不自动改价，也不增加多级预警或复杂的人工确认流程。

## 已确认的业务事实

- Takealot 的品牌筛选页只代表商品品牌，不能确认卖家身份。
- Takealot 的卖家页 `https://www.takealot.com/seller/bestby?sellers=29845693` 表示 Bestby 仍在销售这些商品，但不代表 Bestby 当前持有 Buy Box。
- 商品详情页展示的当前价格和 `Sold by` 才用于判断当前 Buy Box 卖家。
- 一个商品可以继续出现在 Bestby 卖家页，同时详情页显示由其他卖家持有 Buy Box。
- Bestby 的 Takealot 卖家 ID 为 `29845693`。

## 数据源职责

### Takealot Seller API

作为待检查商品的唯一完整基准，提供：

- 店铺 SKU；
- 我方当前售价；
- 库存和启用状态；
- 商品详情链接、PLID、条码和标题等标识。

只有有库存、状态正常且售价有效的 SKU 才进入预警检查。

### Takealot 卖家页

卖家页只作为辅助证据，用于确认商品仍属于 Bestby 在售范围，以及校验商品详情链接。不得把卖家页显示价格直接解释为 Bestby 自己的报价，也不得因商品仍在卖家页就认为 Bestby 持有 Buy Box。

### Takealot 商品详情页

商品详情页是当前 Buy Box 状态的主要依据，读取：

- 当前展示价格；
- `Sold by` 卖家名称；
- 当前变体信息；
- 可用时的 Other Offers 信息。

必须使用后台 SKU 对应的精确商品链接。不得仅凭同一 PLID 的泛化商品数据，把其他颜色、尺寸或套装的价格用于当前 SKU。

## 预警判定规则

对每个有效 SKU，按以下顺序判定：

1. SKU 缺货、已禁用、我方售价无效或无法对应精确变体：不报警。
2. 详情页明确显示 `Sold by` 为当前店铺：不报警。
3. 详情页明确显示 `Sold by` 为其他卖家：判定为丢失 Buy Box并报警，记录当前卖家、前台价格及与我方售价的差价。
4. 无法取得可靠卖家名称，但前台价格低于我方后台售价：报警。
5. 无法取得可靠卖家名称，且前台价格等于我方后台售价：按自家报价处理，不报警。
6. 前台价格高于我方后台售价，或前台价格缺失：不报警。

卖家名称比较应忽略大小写、首尾空格、连续空格和常见展示后缀。店铺识别应支持店铺名称和已配置的 Takealot 卖家 ID；Bestby 对应 `29845693`。

## 数据获取优先级

1. 优先读取精确商品详情页中与当前 SKU/变体一致的 `Sold by` 和价格。
2. Seller API 的商品详情响应仅作为补充，不能用泛化 PLID 结果覆盖已确认的精确变体结果。
3. 公共产品 API 的结果只有在能证明对应当前变体时才参与正式判定。
4. 多个数据源冲突时，以精确商品详情页为准，并在同步统计中记录冲突，不静默混合价格与卖家字段。

## 同步与数据一致性

现有同步在第一批开始前清空旧预警，后续任一批失败都会造成结果残缺。重构后采用完整轮次替换：

- 本轮检查结果先使用唯一运行标识暂存或标记；
- 所有批次成功后，才用本轮结果替换该店铺上一轮有效预警；
- 任一批次失败时，本轮不发布，继续保留上一轮完整预警；
- 同一 SKU 在一次同步中只处理一次；
- 页面必须区分“同步完成”和“同步失败并保留旧结果”。

如果当前数据库结构不适合暂存，可在服务端汇总整轮结果后进行事务式替换；实现方式可以沿用项目现有 Supabase 模式，但必须满足失败不清空旧结果这一行为要求。

## 页面展示

页面继续只显示正式预警，不增加“待人工确认”区域。每条预警展示：

- 店铺和 SKU；
- 商品名称及图片；
- 我方后台售价；
- 当前 Buy Box 价格；
- 当前 Buy Box 卖家；
- 差价；
- 最后成功检测时间；
- 简明原因，例如“Buy Box 已被 Silver Star online 占领”。

同步完成信息应包含检查总数、有效预警数、跳过数和读取失败数。只要存在未完成批次，页面不得宣称本轮同步完成。

## 错误处理

- 单个详情页暂时失败时记录失败原因，不把该 SKU 判为正常。
- 如果本轮存在读取失败，可以完成扫描并显示失败数量，但不得删除上一轮中对应 SKU 的有效预警，除非本轮已经取得足够证据证明预警解除。
- 如果整个批次或同步流程失败，不发布本轮结果。
- 页面解析遇到 Cloudflare、空 HTML、重定向或结构变化时，视为数据不可用，不使用猜测值。

## 验证方案

### 判定单元测试

至少覆盖：

- `Sold by Bestby`，价格等于我方价格，不报警；
- `Sold by` 其他卖家，判定丢失 Buy Box；
- 卖家未知、前台价格低于我方价格，报警；
- 卖家未知、价格等于或高于我方价格，不报警；
- 缺货、禁用、无售价和变体不确定时不报警；
- 卖家名称大小写和空格差异不影响识别；
- 泛化 PLID 数据不得覆盖精确变体结果。

### 同步测试

- 分批检查无重复、无遗漏；
- 中途失败保留上一轮预警；
- 成功完成后才替换旧结果；
- 单个 SKU 读取失败不会被误判为正常；
- 前端统计与数据库最终有效记录一致。

### 真实案例验收

使用已确认案例验证：商品仍出现在 Bestby 卖家页，详情页价格为 `R272` 且显示 `Sold by Silver Star online`。系统应生成 Bestby 丢失 Buy Box 的正式预警，并保存卖家 `Silver Star online` 和价格 `R272`。

## 非目标

- 不自动修改 Takealot 售价；
- 不建立多级风险评分；
- 不增加人工确认队列；
- 不以品牌筛选页作为卖家判断依据；
- 不长期保存无业务需要的价格历史快照。
