# 我的采购订单按装货方式保留同一 SKU 多行设计

## 背景

“我的采购订单”允许同一种产品拆分为不同装货方式，例如同一 SKU 的一部分走“整柜”，另一部分走“冠通”。当前手工新增记录会生成独立 ID，但 Excel 导入只用“店铺 + SKU”匹配待采购记录，导致不同装货方式的导入行可能更新同一条记录，最终只保留一种装货方式。

## 目标

- 同一 SKU 的“整柜”和“冠通”订单必须作为两条独立采购记录保存。
- 重复导入相同 SKU、相同店铺、相同装货方式时，继续更新对应的待采购记录，避免无意义重复。
- 记录进入采购订单池、物流装柜确认和采购 / 在途库存后，仍按各自记录 ID 独立流转。

## 非目标

- 不修改 Supabase 表结构。
- 不改变同一装货方式下重复导入的更新语义。
- 不合并或拆分用户已经保存的历史采购记录。
- 不改变采购数量、金额、CBM 和箱规计算逻辑。

## 设计

### 记录身份

采购记录的持久化身份继续使用独立 `id`。SKU 不是采购记录的唯一键，因此同一 SKU 可以存在多条记录。

### 导入匹配规则

待采购订单的导入匹配键调整为：

```text
采购人账号 + 规范店铺名 + 规范 SKU + 规范装货方式
```

采购人账号仍由当前页面的数据范围限定；实现中的记录匹配键为“店铺 + SKU + 装货方式”。

规范化规则：

- SKU：去除首尾空格并转为大写。
- 店铺：去除首尾空格并转为小写。
- 装货方式：`冠通` 保持为 `冠通`；空值及其他现有默认情况按 `整柜` 处理。

匹配结果：

- 相同店铺、SKU、装货方式：更新最新一条符合条件的待采购记录。
- 相同店铺和 SKU、不同装货方式：创建另一条独立记录。
- 同一份导入文件内，相同店铺、SKU、装货方式的重复行沿用当前合并更新行为。
- `NEW` 或无有效 SKU 的记录沿用当前行为，直接作为独立记录新增。

### 后续流转

采购订单池和 Supabase 保存已经按采购记录 `id` 合并或更新，不应改成按 SKU 去重。不同装货方式的两条记录拥有不同 ID，因此提交采购池、物流确认和进入在途库存时分别保留。

## 错误与兼容处理

- 导入文件没有“装货方式”列时，按“整柜”匹配，保持旧文件兼容性。
- 不对历史数据做自动迁移或复制，避免猜测历史订单应如何拆分。
- 已经被错误覆盖的历史记录不会凭空恢复，需要用户重新新增或重新导入缺失的装货方式记录。

## 验证

增加采购订单导入匹配测试，覆盖：

1. 已有整柜记录，再导入同 SKU 冠通记录，应新增一条。
2. 已有冠通记录，再导入同 SKU 整柜记录，应新增一条。
3. 已有整柜记录，再导入同 SKU 整柜记录，应更新而非新增。
4. 导入装货方式为空时，应按整柜匹配。
5. 同一导入文件中同 SKU 的整柜和冠通行，应各自产生一条记录。
