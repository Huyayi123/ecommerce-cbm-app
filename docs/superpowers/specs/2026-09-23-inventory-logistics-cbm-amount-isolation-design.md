# 采购在途库存物流 CBM 与总金额隔离设计

## 背景

“采购 / 在途库存”编辑表单保存记录时，会无条件重新计算总金额。即使用户只修改物流总 CBM、总重量、日期、状态或备注，也会将原总金额替换为页面重新计算的金额。混装订单的当前页面公式还遗漏混装子产品金额，因此金额变化可能更明显。

## 根因

页面保存统一调用 `withTotalAmount`，该函数每次都写入：

```text
有效采购数量 × 主产品采购单价 + 运费
```

这个行为存在两个问题：

1. 没有区分金额驱动字段和普通字段。
2. 没有包含混装子产品金额。

物流总 CBM 本身没有参与公式，但保存动作触发了无条件重算。

## 目标

- 物流字段与采购金额完全隔离。
- 只有金额驱动字段发生变化时才重算总金额。
- 重算时包含主产品、混装子产品和运费。
- 普通订单、混装订单以及人工保留的历史金额都得到正确处理。

## 字段依赖规则

以下字段变化时重新计算总金额：

- 实际采购数量
- 采购单价
- 运费
- 混装组或混装子产品数量、单价

以下字段变化时保留原总金额：

- 物流总 CBM
- 总重量 kg
- 装货方式
- 装柜日期
- 采购日期、批次日期和批次名称
- 状态
- 备注
- 产品名称、英文名称、图片、厂家、店铺、采购人
- 单品 CBM、采购总 CBM和包装字段

## 金额公式

需要重算时统一使用现有公共函数 `calculatedPurchaseTotalAmount`：

```text
总金额
= 主产品有效采购数量 × 主产品采购单价
+ 所有混装子产品数量 × 对应采购单价
+ 运费
```

页面不再维护一套简化金额公式，避免与公共业务规则分叉。

## 保存流程

1. 开始编辑时保存原记录快照。
2. 保存时比较草稿与原记录的金额驱动字段。
3. 若金额驱动字段未变化，将原 `totalAmount` 原样带入保存记录。
4. 若金额驱动字段变化，调用公共金额函数重新计算。
5. 物流总 CBM和总重量按用户输入独立保存，不参与金额判断或公式。
6. 新增记录没有原快照，按完整金额公式计算初始总金额。

## 兼容性

- 不改变 Supabase 字段和数据库结构。
- 不改变物流总 CBM、采购总 CBM或单品 CBM的现有含义。
- 不自动回写或批量修改历史记录；修复只影响之后的编辑保存。
- 导入和其他页面继续使用各自已有的明确重算规则。

## 测试

- 仅修改物流总 CBM时，总金额保持不变。
- 仅修改总重量、日期、状态或备注时，总金额保持不变。
- 修改主产品数量、单价或运费时，总金额正确重算。
- 混装订单重算时包含全部混装子产品金额。
- 新增普通订单和混装订单使用完整公式生成总金额。
- 生产构建及既有采购、物流、利润测试通过。

## 验收标准

用户在“采购 / 在途库存”中只修改物流总 CBM或其他非金额字段并保存后，单条总金额保持原值；只有数量、价格、运费或混装明细变化时才按包含混装产品的完整公式更新总金额。
