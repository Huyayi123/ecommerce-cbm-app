# 月度利润独立页面、工资与退货明细设计

## 目标

将老板月报从“利润分析”中拆分为左侧独立的“月度利润”页面，增加店铺月工资扣减，并提供可核对的逐笔退货成本明细。

## 导航与权限

- 左侧导航新增“月度利润”，位于“利润分析”和“广告分析”之间。
- “月度利润”仅 `owner` 角色可见和访问。
- 普通 `admin` 继续使用“利润分析”，不能读取月度利润汇总。
- “利润分析”页面移除嵌入的老板月报区域，恢复为单品利润页面。

## 人员工资

- 月度利润表单增加“人员工资 (ZAR)”输入框。
- 工资表示当前店铺所选月份的工资总额，不记录逐个员工。
- 工资选填；留空按 0 计算，填写时必须为 0 或正数。
- 每店每月汇总保存 `salary_cost`，重复同步覆盖。

最终利润公式：

```text
最终利润
= 销售利润
- 退货基础损失
- 退货额外损失
- 广告费用
- 人员工资
```

页面汇总、历史汇总和 Excel 均显示人员工资。

## 退货基础损失明细

- 顶部“退货基础损失”汇总卡片可点击。
- 点击后在汇总卡片下方展开逐笔退货明细，再次点击收起。
- 明细仅保存在当前页面内存，不写入 Supabase。
- 历史数据库快照没有逐笔数据，因此历史月份只能查看汇总。

每笔明细字段：

1. 退货编号
2. 原订单号
3. SKU
4. 产品名称
5. 退货日期
6. 退货数量
7. 采购成本 ZAR
8. 海运费
9. 国内运费
10. 送仓费
11. 分摊的原销售 Total Fees
12. 退货基础损失
13. 退货额外损失
14. 异常原因

所有成本列展示该笔退货数量对应的总额，而不是单件金额。无法匹配原销售或成本资料缺失的退货仍展示，各项不可用成本显示 `-`，该行标红并使月报状态为“不完整”。

## 数据结构与存储

- `MonthlyProfitSummary` 增加 `salaryCost`。
- 新增内存类型 `MonthlyProfitReturnDetail` 保存逐笔退货成本快照。
- `monthly_profit_summaries` 增加非空数值列 `salary_cost`，默认 0。
- 既有历史行通过默认值兼容，不需要重建表。
- 现有内部数据库字段 `return_profit_reversal` 和 `return_net_fees` 保持不变，分别继续保存正数的退货基础损失和退货额外损失。

## Excel

当前同步结果导出四个工作表：

1. 月度汇总
2. SKU明细
3. 销售逐笔明细
4. 退货逐笔明细

历史快照仍只导出月度汇总工作表。

## 验收标准

- owner 左侧看到“月度利润”，普通 admin 看不到。
- “利润分析”不再嵌入月度利润区域。
- 工资留空按 0，填写正数后正确保存、显示、导出并从最终利润扣除。
- 点击“退货基础损失”可展开和收起逐笔退货明细。
- 各成本列等于单件成本乘退货数量，原 Total Fees 按原数量分摊后乘退货数量。
- 逐笔退货基础损失之和等于顶部退货基础损失汇总。
- 无法计算的退货显示异常并标红。
- 当前同步 Excel 有四个工作表，历史汇总只有一个工作表。
- Supabase RLS 仍只允许 owner 访问月度利润。
- TypeScript/Vite 构建通过，现有单品利润、销售明细和退货损失公式不受影响。
