# 装柜计算与采购订单月销量快照设计

## 目标

在“装柜计算”和“我的采购订单”中增加只读“月销量”列。数值由“月销量采购建议”发送时传入并固定保存，只用于查看产品的原始真实销量，不参与任何计算。新品经过倍数转换后的预测月销量只供采购建议计算使用，不得作为订单快照。

## 数据流

1. 月销量采购建议在每一行中同时保留 `rawMonthlySales`（上传文件中的原始月销量）和 `monthlySales`（可能经过新品规则转换的预测月销量）。
2. 建议采购数量、备货月数等现有计算继续使用 `monthlySales`，现有计算结果不变。
3. 生成发送行时，仅将 `rawMonthlySales` 写入装柜计算行的月销量快照字段。
4. 装柜计算保留该原始值并显示为只读列。
5. 从装柜计算生成采购订单时，将原始月销量复制到采购订单记录。
6. 采购订单将原始月销量保存到云端独立字段，后续建议数据变化不会修改历史订单快照。

## 字段与缺失值

- 采购建议行增加 `rawMonthlySales`，明确区分原始销量与预测销量。
- 装柜计算输入行、计算结果行和采购订单类型中的 `monthlySales` 表示原始月销量快照。
- 数据库 `purchase_records` 增加可空数值列 `monthly_sales`。
- 装柜计算行继续通过现有原始数据字段持久化月销量，不增加计算依赖。
- 月销量为 `null` 或未提供时显示 `-`，不能把缺失值显示成 `0`。
- 手工新增、普通 Excel 导入和历史采购订单没有月销量时保持缺失。
- 混装子行没有独立传入的月销量快照时显示空白。

## 页面展示

- 装柜计算：“月销量”位于店铺／采购人之后、采购数量之前。
- 我的采购订单：“月销量”位于采购人之后、计划采购数量之前。
- 两列均为只读文本，不提供编辑控件。
- 月销量不参与采购数量、金额、CBM、状态、排序、筛选或任何业务公式。

## 云端兼容

- 主数据库定义同步增加 `purchase_records.monthly_sales`。
- 增加可重复执行的迁移 SQL，使用 `add column if not exists`。
- 云端映射在读取时把缺失字段转换为 `null`，保存时原样写入数值或 `null`。
- 若云端尚未执行迁移，现有缺列兼容路径仍应给出明确迁移提示，不静默丢失快照。

## 范围限制

- 不改变现有 Excel/CSV 导出字段。
- 不从最新采购建议反向刷新历史订单。
- 不为混装子行推算或关联月销量。
- 不修改任何计算公式。
- 不改变月销量采购建议页面现有的预测月销量展示与新品转换规则。

## 验证

- 普通商品与新品从采购建议发送后，装柜计算均显示上传文件中的原始月销量。
- 新品建议采购数量仍按转换后的预测月销量计算，修正前后结果一致。
- 生成采购订单后月销量正确复制并能在云端重新加载。
- 更新采购建议后，已有采购订单的月销量保持不变。
- 手工新增、普通导入和历史缺失数据显示 `-`。
- 混装子行月销量为空。
- 现有采购数量、金额和 CBM 计算结果不变。
- 项目构建通过。
