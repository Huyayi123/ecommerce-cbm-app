# 海川混装子行与冻结产品列设计

## 背景

海川工作台已经保存主产品和混装产品的 `productDetails`，但当前把所有明细用分号拼接在同一个单元格中。混装产品较多时，产品名称和英文名称会形成极长文本，表格难以阅读。海川产品表横向滚动时，识别产品所需的关键字段也会一起移出视野。

## 目标

参考“我的采购订单”“采购订单池”和“采购 / 在途库存”的显示方式，将海川混装产品拆成主行与浅色混装子行，并在横向滚动时固定产品名称、英文名称、内部编号和 SKU。

## 适用页面

以下四张包含产品的海川表格统一应用：

1. 待入仓
2. 仓库存货 / 海川仓库库存
3. 海川装柜审核
4. 已装柜

物流商绑定和已退回批次摘要不在本次范围内。

## 混装行结构

- 每条海川入仓、库存或装柜记录仍以一个业务主记录为单位。
- `productDetails` 中 `isMixed = false` 的明细作为主产品显示在主行。
- `isMixed = true` 的明细按原顺序显示在主行下方，使用现有 `mixed-child-row` 浅色样式。
- 如果旧数据没有 `productDetails`，继续使用记录本身的产品名称、英文名称、内部编号和 SKU。
- 子行显示自己的产品名称、英文名称、内部编号、SKU、数量、单品 CBM、总 CBM和混装组名称。
- 子行备注说明其与主产品混装，并显示混装组箱数。
- 入仓确认、库存选择、装柜件数、审核输入等业务控件只显示在主行；子行不产生独立操作，避免拆散同一混装箱。
- 混装库存仍必须整批装走，现有禁用部分拆分的规则保持不变。

## 冻结列

四张产品表使用专属海川表格样式，并将以下列从左向右固定：

1. 产品名称
2. 英文名称
3. 内部编号
4. SKU

如果表格前面存在“选择”列，该列保持普通滚动；四个产品字段仍从容器左侧依次吸附。冻结列设置明确宽度、背景色、层级和右侧分隔阴影。表头同时保持纵向冻结。

产品名称和英文名称采用单行省略显示，并通过 `title` 提供完整内容，避免长文本撑宽列。混装子行沿用相同冻结位置和浅色背景。

## 组件结构

在 `HaichuanWorkflowPage` 内增加小型展示辅助函数：

- 获取主产品明细。
- 获取混装子明细。
- 输出四个冻结产品单元格。
- 为各表生成主行后的混装子行。

辅助函数只处理展示数据，不修改海川数据模型、Supabase 字段或 RPC。

## 测试与验证

- 普通产品仍只显示一行。
- 多个混装产品按一项一行显示，不再用分号拼接成长文本。
- 旧数据缺少 `productDetails` 时仍正常显示。
- 四张海川产品表都包含主行与混装子行。
- 横向滚动时四个产品字段保持固定，后续业务列正常滚动。
- 混装库存的部分装柜输入仍保持禁用。
- TypeScript 和生产构建通过。

## 验收标准

海川界面中的混装商品与三个采购页面一样，以主行加浅色子行清晰展示。用户左右滚动任意海川产品表时，始终能看到产品名称、英文名称、内部编号和 SKU，并且现有入仓、库存与装柜数量逻辑不发生变化。
