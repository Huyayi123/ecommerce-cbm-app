# 我的采购订单导入 SKU CBM 回填设计

## 背景

“我的采购订单”上传 Excel/CSV 时，如果表格没有“单品 CBM”或“总 CBM”，解析器会先把对应数值设为 0。当前页面虽然会在展示时用 SKU 资料库补充单品 CBM，但导入保存前没有执行同样的补充，因此云端记录的单品 CBM 和总 CBM 仍为 0。

## 目标

在采购订单导入合并并保存之前，使用 SKU 资料库补充表格中缺失的单品 CBM，并据此计算缺失的总 CBM。表格明确提供的有效数据和已有订单中未被导入字段覆盖的数据必须保留。

## 匹配规则

1. SKU 使用现有标准化规则处理大小写和空白。
2. 同一 SKU 存在多个候选时，优先匹配相同店铺。
3. 表格没有店铺或找不到相同店铺时，使用该 SKU 的第一个候选。
4. 找不到 SKU 资料时维持现有导入结果，不猜测 CBM。

## 字段规则

- 表格提供有效且大于 0 的单品 CBM 时，保留表格值。
- 表格未提供、留空或解析结果不大于 0 时，使用匹配 SKU 的单品 CBM。
- 表格提供有效且大于 0 的总 CBM 时，保留表格值。
- 表格未提供、留空或解析结果不大于 0 时，按有效采购数量乘以最终单品 CBM 计算总 CBM。
- 有确认采购数量时使用确认采购数量，否则使用计划采购数量。
- 计算继续通过现有 `withPurchaseTotals` 规则完成，保持混装、尾箱和金额等现有逻辑不变。
- 更新已有订单时，导入表未提供的字段不应覆盖已有订单中的有效值。

## 数据流

1. `parsePurchaseRecordsFile` 继续负责读取表头、解析原始行，并记录表格实际提供了哪些字段。
2. `MyPurchaseOrdersPage.importOrders` 收到解析结果后，根据页面已有的 SKU 资料索引补充每条导入记录。
3. 对补充后的记录执行总计归一化。
4. 使用现有 `mergeImportedPurchaseOrders` 合并新增或更新记录。
5. 通过现有保存回调写入 Supabase。

这样可以保持文件解析器通用，同时让 SKU 主数据匹配留在已经持有 SKU 资料的页面业务层。

## 异常与兼容性

- SKU 为空、为无法匹配的新品或资料库单品 CBM 也为 0 时，不阻止整份文件导入。
- 本次修改不改变产品名称、图片、厂家、采购价或物流字段的现有导入覆盖规则。
- 不修改采购订单的匹配键、订单池状态或装货方式逻辑。

## 测试

增加针对导入 CBM 回填的自动化测试，至少覆盖：

1. 表格缺少单品 CBM 和总 CBM，成功从 SKU 资料库补齐并计算总 CBM。
2. 表格有单品 CBM但缺少总 CBM，使用表格单品 CBM计算总 CBM。
3. 表格有有效总 CBM，保留表格值。
4. 同 SKU 多店铺时优先匹配相同店铺。
5. 找不到 SKU 时保持 0 且正常导入。
6. 更新已有订单时，缺失字段不覆盖已有有效 CBM。

## 验收标准

上传没有“总 CBM”的采购订单表后，只要该 SKU 能在 SKU 资料库中匹配到有效单品 CBM，保存后的订单就具有正确的单品 CBM 和总 CBM；刷新页面后数值仍然存在，而不是仅在界面临时显示。
