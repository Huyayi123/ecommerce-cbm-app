# 我的采购订单导入改为更新优先

## 目标

“我的采购订单”导入表格时，优先按 SKU 更新当前采购人的待采购订单；没有匹配的商品才新增，避免同一批次重复产生采购订单。

## 匹配规则

- 仅匹配当前采购人名下 `status = pending` 且 `poolStatus = pending_purchase` 的订单。
- SKU 匹配忽略大小写和首尾空格。
- 导入行有店铺时使用“店铺 + SKU”匹配；店铺为空时仅使用 SKU 匹配。
- 同一条件存在多条待采购订单时，只更新最新创建的一条，其余订单保持不变。
- SKU 为空、SKU 为 `NEW` 或没有找到匹配订单时新增。
- 同一导入文件出现重复匹配键时，后面的行覆盖前面的行，只产生一条更新或新增结果。

## 更新规则

- 保留已有订单的 ID、创建时间、采购池状态、采购人分配和工作流关联字段。
- 使用导入行更新商品资料、采购数量、价格、运费、CBM、装货方式、备注等可编辑采购字段。
- 更新后重新计算订单金额和 CBM 汇总。
- 新增行沿用现有导入默认值和当前采购人信息。

## 反馈与验证

- 导入完成提示“更新 X 条，新增 Y 条”。
- 验证单个匹配、重复待采购、无匹配新增、空 SKU/NEW 新增、文件内重复 SKU 和店铺隔离。
- 运行 TypeScript/Vite 生产构建并确认此前“内部编号”采购订单导出功能仍然有效。
