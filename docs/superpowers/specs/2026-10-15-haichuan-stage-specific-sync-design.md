# 海川分阶段数据同步与采购池固定列设计

## 背景

采购订单池、在途库存与海川工作流分别保存采购记录和海川流程快照。当前采购记录被修改后，对应阶段的海川快照不会更新，导致海川“待入库”和“已装柜”仍显示旧数据。同时，采购订单池横向滚动时固定列范围过大。

## 目标

建立两条相互独立、按流程阶段生效的数据同步链路，并将采购订单池的横向固定范围缩减为五列。

## 同步规则

### 采购订单池到海川待入库

当采购订单池中的海川订单保存修改时，仅更新同一 `purchase_record_id` 且状态为“待入库”的海川记录：

- 采购总数量 → 采购总数量
- 总件数 → 申报总件数
- 每箱数量 → 每箱数量
- 尾箱数量 → 尾箱数量

该同步不修改已入库、仓库库存或已装柜数据，也不改写实际入库数量、剩余件数、冻结件数及其他流程状态。

### 在途库存到海川已装柜

当在途库存中的海川订单保存修改时，仅更新同一 `purchase_record_id`、所属批次状态为“已通过”的已装柜产品：

- 总件数 → 装柜件数
- 采购总数量 → 装柜数量

该同步不修改海川待入库和仓库库存，不改写最终 CBM、审核状态、审核时间、批次备注或产品备注。

## 实现设计

- 使用 `purchase_record_id` 作为采购记录与海川记录之间的唯一匹配键，避免按 SKU 或名称误更新重复商品。
- 为两条同步链路提供彼此独立的存储层函数：一个只更新待入库记录，一个只更新已装柜记录。
- 采购订单池保存成功时调用待入库同步；在途库存保存成功时调用已装柜同步。
- 数据更新完成后刷新本地页面数据，保证当前界面立即显示服务端最终结果。
- 同步失败时显示明确错误并重新加载云端数据，避免界面显示已保存但海川数据仍为旧值。
- 对已有海川记录兼容处理；没有对应阶段记录时正常跳过，不创建错误的流程记录。

## 采购订单池固定列

采购订单池横向滚动时仅固定以下五列：

1. 图片
2. 厂家名
3. 内部编号
4. SKU
5. 产品名称

英文名称以及后续所有列取消横向固定。产品名称作为固定区域最后一列，保留右侧分隔阴影。主行、备注高亮行和混装子行继续保持现有背景样式。

## 验证

- 修改采购订单池海川订单的采购总数量、总件数、每箱数量、尾箱数量后，海川待入库对应四项同步更新。
- 上述修改不影响已入库、仓库库存和已装柜记录。
- 修改在途库存海川订单的总件数和采购总数量后，海川已装柜的装柜件数和装柜数量同步更新。
- 上述修改不影响待入库、仓库库存、最终 CBM、审核状态、审核时间和备注。
- 相同 SKU 的不同采购记录不会串改。
- 不存在对应阶段海川记录时保存仍成功。
- 采购订单池横向滚动时只有五列固定，英文名称起正常滚动。
- 项目构建和相关自动化测试通过。

## 范围限制

- 不新增海川流程阶段，不改变入库、装柜审核或库存扣减规则。
- 不修改除上述字段外的海川历史快照。
- 不改变采购订单池字段顺序和编辑权限。
