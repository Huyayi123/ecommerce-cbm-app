# 海川已装柜产品管理员修改设计

## 背景

海川装柜审核通过后，系统会同时更新三个位置：海川仓库库存、海川已装柜明细，以及自动生成的海运在途采购记录。当前管理员删除海运在途记录时，不会同步移除海川已装柜明细或恢复仓库库存，导致页面数据不一致。

本次改为允许管理员直接在“海川仓库库存 → 已装柜”中修改装柜结果。修改必须同步海川仓库和对应海运在途记录，并允许管理员明确选择是否调整仓库库存。

## 目标

- 管理员和所有者可以修改已装柜产品的最终装柜件数、最终装柜数量和最终 CBM。
- 修改件数或数量时，系统按原装柜比例给出建议 CBM，管理员可以覆盖。
- 改小或改大时，由管理员在确认弹窗中选择是否同步调整仓库库存。
- 任一核心装柜值改为零时，整条撤销该产品的装柜结果并恢复仓库库存。
- 海川已装柜、海川仓库和海运在途数据在同一个数据库事务中保持一致。

## 权限

- 只有 `admin` 和 `owner` 可以看到并使用“修改”操作。
- 海川物流商和其他角色只能查看已装柜结果。
- 数据库函数再次校验调用者权限，不能只依赖前端隐藏按钮。

## 页面交互

“已装柜”表格和移动端卡片增加“修改”入口。点击后打开编辑弹窗，显示：

- 产品名称、内部编码和 SKU；
- 原最终装柜件数、数量和 CBM；
- 新最终装柜件数、数量和 CBM；
- CBM 建议值。

修改件数或数量后，按原装柜数据的比例更新建议 CBM。管理员可以直接覆盖 CBM。

保存前根据新旧数据弹出确认：

- 改小：选择“差额恢复海川仓库”或“仅修改装柜与在途，不调整库存”。
- 改大：选择“从海川仓库扣除差额”或“直接修改装柜与在途，不调整库存”。
- 改为零：显示“整条撤销”确认。确认后必须恢复原装柜件数、数量和 CBM，不能选择不调整库存。

确认弹窗显示件数、数量和 CBM 的变化值及库存处理结果。

## 数据库事务

新增管理员数据库函数，输入包括：

- 装柜明细 ID；
- 新装柜件数；
- 新装柜数量；
- 新装柜 CBM；
- 库存处理方式：`adjust_inventory` 或 `keep_inventory`。

函数锁定对应的 `haichuan_loading_items`、`haichuan_loading_batches`、`haichuan_warehouse_lots` 和海运在途 `purchase_records`，并校验装柜批次状态为 `approved`。

### 非零修改

函数更新 `haichuan_loading_items` 的：

- `approved_carton_count`；
- `approved_product_quantity`；
- `approved_cbm`；
- `updated_at`。

选择 `adjust_inventory` 时：

- 改小将差额加回 `remaining_carton_count`、`remaining_product_quantity` 和 `remaining_cbm`；
- 改大从上述剩余库存中扣除差额；
- 重新计算仓库状态并增加版本号；
- 恢复后不得超过初始库存，扣减后不得出现负库存或侵占已冻结库存。

选择 `keep_inventory` 时不修改仓库库存，只修改装柜明细和海运在途副本。

### 改为零

件数、数量或 CBM任一项为零时，按整条撤销处理：

- 将原批准件数、数量和 CBM全部恢复到海川仓库；
- 删除对应 `haichuan_loading_items`；
- 删除对应海运在途 `purchase_records`；
- 同批次没有其他明细时删除空批次；
- 同批次仍有其他产品时保留批次。

### 海运在途同步

对应的在途记录优先使用标准 ID `hc-transit-<loading_item_id>` 查找，并使用装柜批次、来源采购记录和产品标识作为兼容查找条件。

非零修改同步更新：

- `purchase_quantity` 和 `confirmed_purchase_quantity`；
- `carton_count`；
- `total_cbm` 和 `logistics_total_cbm`；
- `total_amount` 和 `freight_cost`，按新旧装柜数量比例重算；
- `updated_at`。

混装记录保持整批修改约束，不允许只修改混装组中的单个子产品或形成部分拆分状态。

## 校验与失败处理

- 新件数、数量和 CBM不得为负数。
- 非零记录必须同时满足件数、数量和 CBM均大于零。
- 选择扣库存时，当前可用库存必须足够。
- 选择恢复库存时，恢复后不能超过初始库存。
- 装柜明细、仓库批次或来源记录不存在时拒绝修改。
- 找不到对应海运在途副本时拒绝非零修改，避免只更新一部分数据。
- 所有数据库更新在一个事务内执行，任一校验或更新失败时整体回滚。
- 前端失败后重新拉取云端数据并显示数据库错误信息。

## 前端数据流

1. 管理员在“已装柜”中点击修改。
2. 前端生成建议 CBM并收集新值。
3. 前端根据差额显示对应库存处理确认弹窗。
4. 确认后调用数据库事务函数。
5. 成功后刷新海川数据和采购记录，使仓库、已装柜和海运在途页面同步。

## 测试范围

- 改小并恢复库存。
- 改小但不调整库存。
- 改大并扣减库存。
- 改大但不调整库存。
- 件数、数量或 CBM改为零时整条撤销。
- 改大且库存不足时拒绝保存。
- 恢复后超过初始库存时拒绝保存。
- 同批次含其他产品时仅修改目标产品。
- 批次最后一条产品撤销后删除空批次。
- 非管理员调用被拒绝。
- 混装记录不能形成部分拆分状态。
- 数据库失败后所有表均保持原值。

## 不在本次范围

- 不允许物流商修改已批准装柜记录。
- 不提供已装柜批次整体批量编辑。
- 不改变首次装柜提交和审核流程。
- 不修改普通整柜物流的确认逻辑。
