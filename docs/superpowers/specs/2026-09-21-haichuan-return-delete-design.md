# 海川采购池退回后允许删除设计

## 背景

采购订单选择“海川”并提交采购订单池后，系统会创建对应的海川待入仓任务。管理员在采购订单池将产品退回采购人时，采购订单会恢复为 `pending_purchase`，但待入仓任务没有同步清理。由于 `haichuan_inbound_items.purchase_record_id` 对采购订单使用限制删除外键，采购人随后无法在“我的采购订单”删除该订单。

## 目标

海川采购订单从采购池退回采购人时，如果对应海川任务仍处于待收货状态，自动清理该待入仓任务，使退回后的订单可以正常编辑或删除。已完成收货的海川数据不得被自动删除。

## 状态规则

- 识别采购记录由 `submitted_to_pool` 转为 `pending_purchase` 的状态变化。
- 仅当原记录装货方式为“海川”时触发待入仓清理。
- 清理函数继续限定 `haichuan_inbound_items.status = pending_receipt`。
- 已收货任务不会被清理；相关采购记录也继续受仓库外键保护，避免误删库存历史。
- 普通整柜和冠通退回逻辑保持不变。

## 实现位置

在 `App.persistPurchaseRecordUpdates` 中统一识别离开海川采购池流程的记录。除现有的“装货方式由海川改为其他方式”外，再覆盖“池状态由已提交改为待采购”的退回场景，并调用现有 `deletePendingHaichuanInboundItems`。

为兼容修复上线前已经退回但仍残留待入仓任务的记录，管理员或所有者从“我的采购订单”删除海川订单时，也先调用同一个待入仓清理函数，再删除采购记录。

将状态判断提取为可独立测试的纯函数，避免页面和云端调用逻辑混在一起。

## 执行顺序与错误处理

1. 保存采购记录的新状态。
2. 删除符合条件的海川待入仓任务。
3. 刷新页面数据。
4. 任一步失败时重新加载云端数据并向用户显示错误。

采购记录先恢复为待采购不会导致已收货数据被删除，因为清理函数只删除 `pending_receipt`。若存在非待收货的关联数据，数据库外键仍会阻止采购订单删除。

## 测试

- 海川记录从 `submitted_to_pool` 退回 `pending_purchase` 时被识别为需要清理。
- 海川记录仍在 `submitted_to_pool` 时不清理。
- 整柜或冠通退回时不触发海川清理。
- 海川装货方式改为其他方式时继续触发现有清理。
- 已收货任务仍由数据库和清理函数的状态条件保护。

## 验收标准

管理员将尚未由海川确认收货的产品从采购订单池退回后，采购人可以在“我的采购订单”成功删除该订单；海川待入仓列表中不再显示该任务，已收货的海川库存记录不受影响。
