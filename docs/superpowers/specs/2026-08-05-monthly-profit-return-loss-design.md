# 月度利润退货损失修正设计

## 目标

修正退货交易费用符号导致退货后利润反而增长的问题。所有退货影响统一表示为正数损失，最终利润只能因退货减少或保持不变。

## 退货损失公式

```text
退货基础损失
= 退货数量 ×（采购成本 ZAR + 海运费 + 国内运费 + 送仓费）
+ 原销售 Total Fees ÷ 原销售数量 × 退货数量

退货额外损失
= max(0, charge-* - reversal-* - payment-*)

总退货损失
= 退货基础损失 + 退货额外损失

最终利润
= 销售利润 - 总退货损失 - 广告费用
```

即使退回商品仍可再次销售，退货发生月也完整扣除采购与物流成本。

## 交易费用符号

- `charge-*` 按绝对金额增加退货额外损失。
- `reversal-*` 和 `payment-*` 按绝对金额抵减退货额外损失。
- 每笔退货的额外损失最低为 0，不允许负费用增加利润。
- 未识别的 transaction 类型不参与计算，并在异常原因中提示，避免未经确认的符号推断。

## 原销售匹配

- 使用 `店铺 + order_id + SKU` 匹配原销售记录。
- 原销售必须具备有效数量、成交金额、Total Fees、采购价和 CBM。
- 无法匹配或原销售费用未结算时，不计算该笔退货基础损失；月报标记“不完整”并累计缺失退货数量。
- 已识别的退货额外损失仍可计入，因为它直接来自该退货记录。

## 页面与导出

- “退货利润冲回”显示名称改为“退货基础损失”。
- “退货净费用”显示名称改为“退货额外损失”。
- SKU 表中的“退货影响”显示基础损失与额外损失之和，使用正数。
- SKU 净利润等于销售利润减退货影响。
- 月度汇总和 Excel 使用相同名称与正数损失口径。
- 数据库字段暂时保持不变，避免为显示名称变化进行破坏性迁移；字段值改为正数损失。

## 验收标准

- 任意退货记录都不能使最终利润增加。
- `charge-*` 100、`reversal-*` 30、`payment-*` 20 时，退货额外损失为 50。
- 抵减金额超过 charge 时，退货额外损失为 0。
- 退货基础损失包含采购成本、海运费、国内运费、送仓费和按退货数量分摊的原 Total Fees。
- SKU 净利润与月度最终利润使用同一退货损失方向。
- 无法匹配原销售时状态为“不完整”，且不会显示虚假的零成本正常结果。
- TypeScript/Vite 构建通过，销售逐笔明细与取消订单过滤不受影响。
