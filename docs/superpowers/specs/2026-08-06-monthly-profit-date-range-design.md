# 月度利润日期范围选择设计

## 目标

将月度利润的单一月份输入改为同一自然月内的开始日期与结束日期选择，允许老板统计月内任意区间，同时继续保留 7 天费用结算延迟。

## 日期选择

- 使用日期范围选择器，一次展开日历完成开始日期与结束日期选择。
- 第一次点击设置开始日期，第二次点击设置结束日期。
- 已选择区间在日历中高亮。
- 第二次选择早于当前开始日期时，该日期成为新的开始日期，并等待重新选择结束日期。
- 开始日期和结束日期必须位于同一个自然月，禁止跨月。
- 可选结束日期最大为南非当天减 7 天；未来和费用结算期内日期不可选择。
- 未完整选择开始和结束日期时，同步按钮不可用。

## 页面文字

- 表单“月份”改为“统计日期”。
- 页面删除“数据截止日……”提示。
- 保留月报完整性提示，但只显示“状态：完整”或“状态：不完整（最终利润为已知数据结果）”。
- Excel 与历史汇总使用“统计开始日期”和“统计结束日期”，不再展示“数据截止日”。

## 查询规则

- 销售 API 使用所选 `date_from` 和 `date_to`，首尾日期均包含。
- 退货 API 使用相同日期范围。
- 退货 Total Fees 的历史回退仍以所选结束日期为基准向前查询 180 天。
- 业务日期继续使用南非 SAST。

## 保存与唯一性

每条汇总的唯一范围为：

```text
店铺 + 统计开始日期 + 统计结束日期
```

- 相同范围重复同步时覆盖。
- 同一店铺、同一自然月可以保存多个不同日期范围。
- SKU、销售和退货逐笔明细仍只保留在当前页面内存，不写入 Supabase。
- 页面刷新后的历史范围只能查看和导出汇总。

## 数据结构与迁移

- `MonthlyProfitSummary` 增加 `dateFrom` 和 `dateTo`。
- 保留既有 `month` 字段用于兼容和月份归类，但不再作为唯一键。
- `monthly_profit_summaries` 增加非空 `date_from`、`date_to` 日期列。
- 旧数据迁移时：`date_from` 使用月份第一天，`date_to` 使用原 `data_cutoff_date`；若原截止日不在该月份内，则使用该月份最后一天。
- 删除原 `shop_name + month` 唯一约束。
- 新增 `shop_name + date_from + date_to` 唯一约束。
- 汇总 ID 改为 `店铺 + 开始日期 + 结束日期`，避免同月不同范围冲突。
- `data_cutoff_date` 暂时保留供旧数据兼容，但新记录写入所选结束日期，页面和导出不再显示该字段。

## 历史记录交互

- 选择店铺和完整日期范围后，按精确范围查找历史汇总。
- 切换店铺、开始日期或结束日期时，清空当前内存中的 SKU、销售和退货明细。
- 当前同步结果可导出四个工作表：月度汇总、SKU明细、销售逐笔明细、退货逐笔明细。
- 历史范围仅导出月度汇总。

## 验收标准

- 日历可选择同月起止日期并高亮完整区间。
- 无法选择跨月范围或南非当天减 7 天之后的日期。
- 销售和退货查询严格使用所选首尾日期。
- 页面不再显示“数据截止日”。
- 相同店铺和相同日期范围重新同步会覆盖历史汇总。
- 同店同月的不同范围可分别保存。
- 旧月报迁移后仍可读取。
- 退货 180 天费用回退以所选结束日期为基准。
- 当前明细与历史汇总导出规则保持不变。
- TypeScript/Vite 构建通过，owner RLS、利润公式、工资和退货匹配规则不受影响。
