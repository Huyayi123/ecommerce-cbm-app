# 混装子行件数修复设计

## 目标

混装子行表示某个商品拼入主商品已经存在的箱子，不代表新增物流箱。因此，所有页面与 Excel 导出中的混装子行“件数／总件数”必须留空，不参与箱数合计。

## 统一规则

- 主商品行继续记录实际整箱件数、尾箱数量和总件数。
- 混装子行的整箱件数、每箱数量、尾箱数量及总件数统一留空。
- 混装子行继续显示产品数量、采购单价、金额、单品 CBM 和总 CBM。
- “是否混装”继续显示“混装子行”。
- “混装组”或备注继续显示组名及该组所依附的箱数，例如“混装1 1件”，用于识别拼入哪个箱组，但该数字不进入混装子行的件数列。
- 不修改 `mixedGroups[].cartonCount` 原始数据，因为它仍用于描述混装组及主商品的装箱关系。

## 修改范围

1. “我的采购订单”表格：混装子行总件数留空。
2. “采购订单池”表格：混装子行总件数留空。
3. 通用采购记录 Excel／CSV 导出：混装子行“件数”留空。
4. 我的采购订单专用导出模板：混装子行“件数”由 `0` 改为空，保持与其他导出一致。
5. “采购／在途库存”页面已经留空，保持现状。

## 不变内容

- `packageCountFor` 继续只计算主商品整箱件数加尾箱是否存在。
- 增加或删除混装组不改变主商品总件数。
- 混装产品的采购数量、金额及 CBM 计算不变。
- 不修改数据库结构或已有混装数据。

## 验收

- 页面中的混装子行总件数为空。
- Excel／CSV 中的混装子行“件数”为空，不再出现 `1` 或 `0`。
- 主商品行的总件数保持原值。
- 混装组列仍能看到“混装1 1件”等关系说明。
- 混装子行的产品数量、金额和 CBM 保持正确。
- 生产构建通过，其他采购和物流流程不受影响。
