# SKU 导入保留云端内部编号设计

## 根因

读取 SKU 资料时，前端会为缺少内部编号的记录临时补号。批量导入保存时又读取了这些补号后的数据，导致临时编号被写回数据库；若该编号仍被另一条数据库记录占用，批量 upsert 会触发 `sku_items_internal_code_idx` 唯一索引错误。

## 修复规则

- 保存前读取数据库原始 SKU 数据，不使用页面展示时临时补出的内部编号。
- 已存在于数据库的记录始终保留数据库原始内部编号，包括空编号。
- Excel 未提供内部编号时，不更新已有记录的内部编号。
- 只有真正新增且没有可用内部编号的记录才自动分配编号。
- 新编号从数据库现有最大有效五位编号之后开始分配，不复用旧编号空档。
- 如果新增记录携带的编号与数据库编号冲突，也改为分配新编号。

## 范围

- 不修改 SKU、TSIN、名称、价格、CBM 和图片等业务字段。
- 不修改数据库索引或表结构。
- 页面展示仍可为旧的空编号记录显示临时编号，但保存更新时不会写回该临时编号。

## 验证

- 纯更新导入不会改变任何已有记录的内部编号。
- 数据库中内部编号为空的已有记录导入后仍为空。
- 新增 SKU 获取大于数据库当前最大编号的新编号。
- 新增记录不会与已有编号冲突。
- TypeScript 与 Vite 生产构建通过。
