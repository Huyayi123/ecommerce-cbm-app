# 错误采购导入数据清理设计

## 目标

清理 2026-09-23 下午误导入的 `111.xlsx` 和 `111 - 副本.xlsx` 所产生的采购/在途库存数据。清理范围以数据库实际写入结果为准，不以“当前是否重复”为判断条件。

## 时间边界

- 北京时间：2026-09-23 16:30:00 至 18:00:00。
- 数据库查询使用对应的 UTC 时间，并采用左闭右开区间，避免边界重复。
- 新建候选以 `created_at` 落入时间窗口为准。
- 旧记录受影响候选以 `created_at` 早于窗口、`updated_at` 落入窗口为准。

## 管理员入口

在采购/在途库存页面提供一次性、仅管理员可见的清理入口。入口默认使用上述固定时间窗口，不允许普通用户操作。

入口分为两个阶段：

1. 只读预览：查询候选记录、分类、统计，并生成备份。
2. 执行清理：只删除预览结果中的新建候选；旧记录受影响候选单独展示，不自动删除。

## 候选分类

### 新建候选

满足以下全部条件：

- `created_at` 位于时间窗口内；
- 业务字段与两份错误 Excel 中至少一条记录匹配；
- 当前记录属于采购记录表。

这些记录是批量删除对象。Excel 的 2,157 行可能因同一 SKU、店铺和装货方式合并而对应较少的数据库记录，因此删除数量不要求等于 Excel 行数。

### 旧记录受影响候选

满足以下全部条件：

- `created_at` 早于时间窗口；
- `updated_at` 位于时间窗口内；
- 业务字段与错误 Excel 匹配。

这些记录可能是导入时被合并更新的原有“待采购”记录。为防止删除历史正常数据，本次不自动删除，只导出清单供恢复或后续人工处理。

## 匹配规则

匹配逻辑复用采购表格导入时的字段规范化规则，包括：

- SKU 去除首尾空格并统一大小写；
- 店铺、采购人、装货方式和状态使用系统规范值；
- 数字字段按系统精度比较；
- 空 SKU 和 `NEW` 记录使用厂家、产品名称、英文名称、店铺、采购人、数量、日期、装货方式等组合字段匹配；
- 同一 Excel 行只作为匹配依据，不要求数据库中只有一条同内容记录。

## 备份与删除

- 删除前把全部新建候选和旧记录受影响候选导出为带数据库 ID、`created_at`、`updated_at` 的 Excel 或 JSON 备份。
- 备份成功后才允许进入删除确认。
- 删除请求只接受预览阶段生成的明确数据库 ID 列表，不能再次按宽泛条件直接删除。
- 删除分批执行，并记录成功、失败及失败原因。
- 如果任一批次失败，停止后续批次并保留已完成结果，页面提供失败 ID 清单。

## 权限和确认

- 入口仅对管理员显示。
- 预览和导出备份不修改云端数据。
- 删除按钮显示待删除准确数量和时间范围。
- 执行删除前必须再次确认；确认文字明确说明删除不可由页面直接撤销，只能通过备份恢复。

## 验证

清理后重新加载采购记录并核对：

- 已删除数量等于删除成功 ID 数量；
- 时间窗口内、与错误表匹配的新建记录剩余为 0；
- 旧记录受影响候选仍然存在；
- 在途 SKU、采购数量、总金额和 CBM 汇总重新计算；
- 随机抽查 `NEW`、普通 SKU、整柜、冠通、海川和混装记录。

## 非目标

- 不清理该时间窗口之外的历史重复记录。
- 不修改采购导入的长期去重策略。
- 不自动恢复无法从现有数据推导出原值的旧记录。
