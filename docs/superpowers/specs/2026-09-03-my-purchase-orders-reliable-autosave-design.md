# 我的采购订单可靠自动保存设计

## 问题

“我的采购订单”普通字段当前在 `onChange` 中写入 React 草稿状态，在 `onBlur` 中从草稿状态读取并保存。变更和失焦连续发生时，保存函数可能读取到更新前的草稿，导致第一次修改不生效。

每次保存还会提交完整采购记录。用户连续修改同一行多个字段时，如果前一次保存尚未结束，后一次可能以旧记录为基础提交，从而覆盖前一次字段。Supabase 实时刷新会放大这种竞态。

## 目标

- 输入一次即可可靠保存，不要求重复点击或修改。
- 同一行连续修改多个字段时合并为最新记录，不互相覆盖。
- 保持输入时立即显示，不因云端刷新闪回旧值。
- 控制数据库请求数量，不按每个按键立即请求。
- 保存失败时保留用户草稿并显示错误。

## 保存交互

### 文本和数字字段

- `onChange` 立即更新本地草稿，因此页面即时显示。
- 用户停止输入约 600ms 后自动保存该行最新草稿。
- `onBlur` 或按 Enter 时立即刷新并提交该行最新草稿，不等待剩余防抖时间。
- 同一行多个字段在一次提交前合并到同一份采购记录。

### 日期、状态和装货方式

- 选择后立即保存。
- 保存使用事件中的当前值，不依赖 React 状态是否已经完成更新。
- 不再依赖额外的失焦事件，避免重复保存。

### 混装字段

- 保留现有约 700ms 自动保存体验。
- 混装保存与普通字段保存共用同一记录的串行队列。
- 保存前合并该记录尚未提交的普通草稿和混装草稿，避免一类保存覆盖另一类。

## 每行串行保存

保存以采购记录 ID 为粒度：

1. 每条记录同时最多只有一个云端保存请求。
2. 保存进行中产生的新修改继续保留为待保存版本。
3. 当前请求结束后，如该行又有变化，立即保存最新合并版本。
4. 中间版本可以合并跳过，但最终最新版必须保存。
5. 不同记录可以独立保存，互不阻塞。

## 草稿清理与失败处理

- 只有确认某个字段的当前草稿值已经成功保存后，才清理该字段草稿。
- 如果保存期间字段又被修改，只清理旧版本，不清理新值。
- 保存失败时保留未保存草稿，显示具体错误，允许失焦、Enter 或继续编辑后重试。
- 云端 props 更新时，仍优先显示本地未保存草稿。

## 业务计算

- 数量、采购单价、运费、箱规和尾箱变化继续重新计算总金额、实际数量与 CBM。
- 人工填写总金额时沿用现有人工值逻辑。
- 不改变采购池提交、订单导入、权限、混装计算和删除逻辑。

## 验证

1. 输入字段后立即失焦，保存使用最新事件值。
2. 连续修改同一行两个字段，最终记录同时保留两个新值。
3. 第一次保存进行中再次修改，完成后自动提交最新版。
4. 日期、状态和装货方式选择后只触发一次即时保存。
5. 保存成功只清理已经提交的草稿版本。
6. 保存失败保留草稿并可重试。
7. 普通字段和混装字段连续修改时不会互相覆盖。
8. 我的采购订单现有导入与采购池流转测试通过。
9. TypeScript 生产构建通过。
