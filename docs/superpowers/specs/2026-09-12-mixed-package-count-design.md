# 混装总件数计算修正设计

## 背景

当前采购记录的总件数会把整箱、尾箱和混装组件数相加。当主商品存在尾箱，同时新增一个用于描述该尾箱内容的混装组时，系统会把同一个物理箱子计算两次。

## 业务规则

混装表示不同 SKU 共用已有箱子，不产生额外的物理件数。总件数统一按以下公式计算：

```text
总件数 = 整箱件数 +（尾箱数量 > 0 时计 1 件）
```

混装组中的“件数”字段继续保留，用于描述混装箱数量和组成，但不参与总件数汇总。

## 实现范围

- 修改采购记录共用的 `packageCountFor` 函数，移除混装组件数加项。
- 使用该函数的“我的采购订单”、采购订单池、采购 / 在途库存及相关 Excel 导出会自动采用新公式。
- 不修改页面字段布局，不删除混装组“件数”。
- 不修改已有采购记录或混装明细数据，无需数据库迁移。

## 保持不变

- 混装商品数量继续参与对应 SKU 的实际数量计算。
- 混装商品采购金额、单品 CBM 和总 CBM 计算保持不变。
- 混装组名称、件数和 SKU 行继续保存和显示。
- 物流商的装走整箱、装走尾数、留下整箱、留下尾数及审核写回逻辑保持不变。
- 冠通、整柜和海川的装柜方式流程保持不变。

## 示例

- 整箱 `3`、尾箱 `0`、混装组 `1` 件：总件数为 `3`。
- 整箱 `0`、尾箱 `40`、混装组 `1` 件：总件数为 `1`。
- 整箱 `3`、尾箱 `10`、混装组 `2` 件：总件数为 `4`。
- 整箱 `0`、尾箱 `0`、混装组 `1` 件：总件数为 `0`；混装组只描述箱内组成，不单独创造箱件。

## 测试

新增或扩展采购记录计算测试，覆盖：

1. 只有整箱时按整箱数计算。
2. 有尾箱时只增加一件。
3. 新增一个或多个混装组不改变总件数。
4. 修改混装组件数不改变总件数。
5. 混装数量、金额和 CBM 的原有计算继续通过。
6. 项目全部现有测试及 `npm.cmd run build` 通过。
