# 采购订单导入总金额与混装内部编号修复设计

## 背景

“我的采购订单”导入文件中的金额列可能使用“混装总金额”表头。当前解析器只识别“总金额”“金额”和 `total_amount`，因此无法读取“混装总金额”，并错误回退为采购数量乘采购单价。混装子行在页面和导出文件中又直接复用了主商品内部编号，导致不同 SKU 显示相同编号。

## 已验证样本

测试文件 `购物清单9月11日-孙杰 - 副本.xlsx` 的“SKU导入模板”工作表包含“运费”和“混装总金额”列：

- 50 × 15.6 + 75 = 855，报表混装总金额为 855。
- 48 × 23 + 80 = 1184，报表混装总金额为 1184。
- 30 × 37 + 90 = 1200，报表混装总金额为 1170，说明报表总金额可能包含人工优惠或调整，不能强制覆盖。

## 设计

### 导入金额

- 将“混装总金额”和“含混装总金额”加入采购订单 `totalAmount` 的表头别名。
- 表格提供非空总金额时，将其视为最终金额并原值保存。
- 表格总金额为空时，按以下公式计算：

```text
总金额 = 实际采购数量 × 采购单价 + 运费 + 混装商品金额
```

- 更新已有待采购记录时继续遵守“只更新表格非空字段”的规则。
- 如果表格未提供总金额，但数量、单价、运费或混装明细发生变化，重新计算总金额。

### 混装内部编号

- 主商品继续显示采购记录自身的内部编号。
- 每个混装子行使用其自身 SKU 匹配 SKU 资料库，并显示匹配产品的内部编号。
- 无法匹配或资料库未填写内部编号时显示 `-`。
- “我的采购订单”页面与 Excel/CSV 导出使用同一匹配规则。
- 内部编号只属于产品，不跟随箱子、混装组或主订单。

## 测试

- 使用用户提供的报表验证 855、1184、1170 均按原值导入。
- 验证“混装总金额”和“含混装总金额”两种表头。
- 验证总金额为空时包含运费和混装商品金额。
- 验证导入更新只修改非空字段。
- 验证同一混装组内不同 SKU 显示各自内部编号，主商品编号不被复用。
- 验证 SKU 无匹配时显示 `-`。
- 验证页面和 Excel/CSV 导出的内部编号一致。
- 运行相关单元测试及 TypeScript/Vite 生产构建。

## 范围

本次不改变采购金额业务公式、SKU 匹配键、混装数据结构或数据库表结构。
