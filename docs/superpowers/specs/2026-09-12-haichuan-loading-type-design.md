# 海川装柜方式与物流商隔离设计

## 背景

系统现有装柜方式为“整柜”和“冠通”。现在新增“海川”：海川与整柜采用相同的业务流程，都需要设置装柜日期、分配物流商、由物流商确认装柜并由管理员审核；但海川与现有整柜不是同一家物流商，生成物流批次时必须相互隔离。

## 目标

- 所有涉及装柜方式的录入、编辑、筛选、导入、导出和存储均支持“海川”。
- 同一 SKU 的整柜、冠通和海川记录能够分别存在，不因导入或更新而合并为同一条。
- 整柜和海川都走物流商确认流程，但生成的物流批次严格按装柜方式隔离。
- 冠通现有的独立直发在途库存流程保持不变。
- 不修改采购数量、库存计算、采购人退回、提成或其他无关功能。

## 装柜方式定义

采购记录的装柜方式允许以下值：

- `整柜`
- `冠通`
- `海川`
- 空值，仅用于兼容历史数据；现有页面继续按整柜显示和处理。

系统中所有装柜方式下拉框均增加“海川”。采购 / 在途库存的装柜方式筛选也增加“海川”。

## 数据导入、导出与记录身份

- Excel 和 CSV 导入时精确识别“海川”。
- 未提供装柜方式或提供未知值时，沿用现有兼容规则，不改变历史默认行为。
- 采购订单导入匹配键继续使用“店铺 + SKU + 装柜方式”；规范化后整柜、冠通和海川是三个不同值。
- 相同店铺、SKU、装柜方式继续更新对应的待采购记录；装柜方式不同则新增独立记录。
- 所有现有导出继续使用当前字段结构，装柜方式为海川时原样输出“海川”。

## 采购订单池流程

### 统一装柜日期

- “统一本池装柜日期”处理整柜和海川记录。
- 已逐行填写、且不同于原本统一日期的人工日期继续保留。
- 冠通继续跳过，不改变日期。
- 页面提示文案由“整柜订单”调整为“整柜/海川订单”，同时继续单独报告跳过的冠通数量。

### 修改装柜方式

- 管理员可以把采购池记录改为整柜、冠通或海川。
- 任意装柜方式发生变化时继续清空该记录的装柜日期，避免继承另一条物流路线的日期。
- 后续由管理员统一日期或逐行重新填写。

### 冠通直发

“发送已填日期的冠通到在途库存”仍只处理冠通。整柜和海川不会进入该操作。

## 物流批次隔离

采购订单池和物流装柜确认页的管理员批次生成区增加“装柜方式”选择，仅提供：

- 整柜
- 海川

管理员选择装柜日期、装柜方式和物流商账号后生成批次。批次明细只包含同时满足以下条件的记录：

- 位于采购订单池且未取消；
- 装柜日期与所选日期一致；
- 装柜方式与所选方式一致；空历史值只在选择整柜时兼容纳入；
- 尚未进入在途库存。

批次身份由“装柜日期 + 装柜方式 + 物流商账号”共同区分。即便同一账号被用于两种装柜方式，整柜和海川也不会共用或覆盖批次。旧批次保持可读取、可审核，不做破坏性迁移。

物流商账号仍只能看到分配给自己的批次。因为每个新批次只包含一种装柜方式，不同物流商不会看到或处理对方路线的记录。

## 数据库兼容性

本次不新增数据库字段或表。采购记录和物流批次明细现有文本字段可以保存“海川”。装柜方式参与新批次 ID 的生成，但无需修改 Supabase 表结构。

## 错误处理

- 未选择装柜方式、物流商账号或有效装柜日期时，不生成批次并显示明确提示。
- 所选日期和方式没有符合条件的记录时，不保存空批次。
- 保存失败沿用现有错误提示，不改动原采购记录。

## 测试与回归范围

自动测试至少覆盖：

1. 类型、本地存储和文件导入接受海川。
2. 同一 SKU 的整柜、冠通、海川分别保留为三条记录。
3. 统一日期更新整柜和海川，但不更新冠通。
4. 冠通直发只处理冠通。
5. 生成整柜批次时不包含海川，生成海川批次时不包含整柜或冠通。
6. 相同日期和物流商下，整柜与海川使用不同批次 ID。
7. 现有采购订单导入、采购池分流、物流审核和选择导出回归测试继续通过。
8. `npm.cmd run build` 通过。

## 非目标

- 不自动把物流商账号永久绑定到某一种装柜方式。
- 不新增“海川专属账号角色”。
- 不改变冠通物流字段、直发条件或按钮含义。
- 不改变整柜和海川审核通过后的在途库存写回规则。
- 不改动无关页面布局或其他业务计算。
