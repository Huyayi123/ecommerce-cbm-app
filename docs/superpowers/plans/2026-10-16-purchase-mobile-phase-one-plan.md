# 我的采购订单移动端适配实施计划

## 1. 保持业务边界

- 仅修改 `MyPurchaseOrdersPage` 的移动端显示状态和 `styles.css` 的响应式规则。
- 继续复用现有新增、字段草稿、自动保存、混装、提交、删除、导入和导出函数。
- 不修改类型、计算工具、存储接口、数据库、权限判断或桌面表格。

## 2. 移动端列表摘要

- 保留现有卡片和折叠详情结构。
- 在卡片摘要补充内部编码、总金额和混装标识。
- 将详情入口文案调整为查看全部字段；编辑通过独立入口进入全屏表单。
- 保留采购链接、混装和删除操作。

## 3. 新增与编辑全屏表单

- 增加本地界面状态，记录新增表单是否打开及当前编辑记录。
- 将新增字段复用到桌面原表单和手机全屏表单，不复制业务计算。
- 手机点击新增订单打开全屏表单；新增成功后关闭，失败时保留输入内容。
- 手机点击编辑打开当前记录的全屏表单，继续使用现有草稿与自动保存机制。
- 表单顶部提供返回，底部提供新增/完成；打开时隐藏全局手机底部导航。

## 4. 批量操作

- 桌面顶部批量按钮保持不变。
- 手机端未选择记录时不显示批量操作条。
- 选择记录后在底部导航上方显示选择数量、提交选中和删除选中。
- 所有按钮继续调用现有批量函数及确认逻辑。

## 5. 响应式样式

- 全屏表单限定在手机媒体查询内，使用安全区域并允许纵向滚动。
- 固定标题栏和操作栏，正文为单列字段。
- 为页面底部增加足够留白，避免批量操作条覆盖卡片。
- 桌面端隐藏手机专用入口、全屏容器和批量操作条。

## 6. 验证

- 运行 TypeScript 与 Vite 生产构建，确认 PWA 产物正常。
- 运行全部现有业务测试，特别确认采购订单导入、采购池流转和数量计算。
- 检查采购员、管理员、所有者和只读角色的操作可见性。
- 检查新增成功/失败、编辑自动保存、批量提交、批量删除和混装入口。
- 在常见手机宽度检查无横向溢出，并确认桌面布局无变化。
